# Audit et simplification — 12 octobre 2026

Le projet dispose d’un moteur déterministe testé et d’une séparation utile entre
calculs, explications IA et archives. L’accumulation touche surtout la présentation :
les fonctions avancées occupaient autant de place que le parcours quotidien.
La livraison 0.3.6 simplifie ce parcours sans modifier les probabilités.

## Constats et corrections

| Constat | Correction livrée |
|---|---|
| Sept onglets au même niveau, accueil sur les cotes | Accueil sur Pronos ; Pronos, Suivi et Calendrier au premier niveau |
| 25 compétitions et leurs compteurs affichés en permanence | Liste repliable ; filtre disponible aussi sur petit écran |
| Statistiques d’archives et textes répétés sur toutes les pages | Suppression des panneaux génériques ; chiffres de suivi conservés dans Suivi |

| Cartes encombrées par les dates de calcul et la profondeur d’historique | Détails accessibles dans un panneau repliable ; probabilités et motifs d’abstention restent visibles |

Les formulaires restent utilisables sans JavaScript côté tableau. Le chat conserve
ses actions explicites et son jeton ; aucun appel IA ni collecte sportive n’a été
lancé pour cet audit. L’aperçu de contrôle utilise les fichiers locaux et simule
l’indisponibilité des modèles pour ne pas solliciter les comptes.

## Mesures locales

Médiane de cinq générations HTML par vue, ancien et nouveau code alternés dans
le même processus, mêmes données locales, sans réseau ni modèle IA. Ces mesures
portent sur le rendu Python ; elles ne mesurent ni le chargement complet du navigateur
ni les appels aux spécialistes. Elles ne constituent pas un test de charge.

| Vue | Avant | Après |
|---|---:|---:|
| Calendrier | 129.5 ms | 1.9 ms |
| Pronos | 268.2 ms | 138.0 ms |
| Résultats | 132.1 ms | 118.0 ms |
| Sources | 147.7 ms | 133.1 ms |

Le gain principal vient des lectures inutiles supprimées. Aucun cache supplémentaire
n’a été introduit : les fichiers et dates continuent d’être lus lors des calculs.

- Code Swift vérifié ; application construite pour arm64 et x86_64 ; signature locale
  vérifiée et contrôle d’intégrité du DMG réussi. Avertissement de l’éditeur de liens

  Le match Lens / Sporting CP, la coupe UCL et la période J+1 à J+3 sont bien conservés
  du tableau au coach puis au retour. Aucun appel réel aux modèles pendant ce contrôle.

## Ce qui reste à améliorer

Le HTML, le CSS et le JavaScript restent embarqués dans les modules Python, souvent
sur de très longues lignes. Les séparer en fichiers dédiés faciliterait les évolutions,
mais demande de vérifier leur inclusion dans l’installation et le paquet Mac. Cette
migration n’est pas nécessaire au gain de performance livré et n’a pas été engagée.

Le tableau d’un workspace simple et celui du hub restent deux vues différentes.
Le premier sert encore au démarrage et à la démonstration : le supprimer ferait perdre
un parcours existant. Les fonctions d’évaluation et les dossiers d’agents sont conservés
comme outils avancés plutôt que supprimés.

Les nombreux anciens dossiers de construction et DMG représentent environ 41 Mo
avant intervention. Ils sont conservés comme anciennes livraisons. Seules les copies
intermédiaires créées par le nouveau script sont désormais nettoyées après succès.

Le dossier courant n’est pas un dépôt Git. Une sauvegarde des fichiers modifiés avant
intervention est dans `data/maintenance-backups/20261012-ux/`, avec leur arborescence
originale. Les nouveaux guides et ce rapport s’ajoutent au projet. Les historiques,
prévisions, analyses, journaux et préférences utilisateur n’ont pas été nettoyés.

## Utiliser la livraison

En développement, arrêter puis relancer le serveur local pour charger le nouveau code.
Pour l’application installée, utiliser `dist/AI-Prono-Coach-0.3.6.dmg` : l’ancienne app
ne se met pas à jour automatiquement à partir du code de ce dossier. Le paquet est signé
localement, sans notarisation Apple. L’app installée n’a pas été remplacée par cet audit.
